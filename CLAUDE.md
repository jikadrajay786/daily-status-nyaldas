# Daily Status

npm-workspaces monorepo for a Daily Status Tracker: `apps/desktop` (Electron), `apps/mobile` (Expo SDK 58), and `packages/core` (code both share). The product is for **non-technical staff**. Keep UI copy in plain everyday language, keep editor tools non-technical (no code formatting), and show friendly errors (`errMsg` in `lib/useQuery.ts` maps Supabase messages to translation keys).

UI languages: English, Hindi, Gujarati (`lib/i18n.ts`). The UI language picker lives only in the desktop sidebar and the mobile Settings tab (sign-in follows the saved choice, else the system language). Every user-visible string goes through `t()` from `useT()`; `hi`/`gu` are typed against `en`, so a missing translation fails typecheck. Use everyday Hindi/Gujarati with familiar loanwords (सबमिट, लॉग इन), not formal terms. The editor's "Write in" picker does phonetic typing (English letters → Hindi/Gujarati) via `packages/editor/src/transliterate.ts`, which calls Google Input Tools (free, unofficial, needs `https://inputtools.google.com` in the CSP). Failures must leave the typed letters untouched. Words convert on space/punctuation via `handleTextInput` and on Enter via keydown, never both: Android keyboards report keydown as "Unidentified". Don't use `window.confirm` (its buttons follow the OS language). When testing with Playwright, quit any running `npm run dev` first or pass `--user-data-dir`, or localStorage silently won't persist. Desktop stack: **Electron + electron-vite + React 19 + TypeScript + Tailwind v4 + Supabase**. Paths below are relative to `apps/desktop` unless they start with `packages/` or `apps/mobile`.

Layout:

- `packages/editor/src/`: the status editor UI (web-only React + TipTap + Tailwind): `DescriptionEditor` (Write-in picker, chips, copy-plan, suggestions; `compact` = phone layout), `Toolbar`, `LangPicker`, `commands`, `marks`, `transliterate`, `sanitize` (DOMPurify configured from core's allowlist; desktop cards and the mobile editor page both use it), and `theme.css` (the `@theme inline` token mapping, `.rich` styles, and an `@source` so importing apps scan these files). Desktop renders it directly; mobile renders the same component inside a DOM component. It takes the saved Write-in language as props (`initialWriteLang`/`onWriteLangChange`): no storage access here.
- `packages/core/src/`: platform-free TypeScript shared by both apps, imported as `@daily-status/core/<module>` (raw TS, no build step; Vite and Metro compile it). Holds `supabase.ts` (`initSupabase(url, key, storage?)` once per app, then `db()`/`unwrap()`/`today()`), `database.types.ts`, `statusService`, `adminService`, `useAuth`, `useQuery`/`errMsg`, `useDebounced`, `i18n` (dictionaries, `translator`, `useT`), `format`, `workdays`, `richText` (the editor's markup allowlist and palette, `richTree` = htmlparser2 parse + sanitize to a node tree, `extractPlan`/`loadPlanBefore`, `parseDraft`). Hermes has no `Intl.Segmenter` (`firstGrapheme` falls back to a virama-aware regex). ESLint bans browser globals (`window`, `document`, `localStorage`, `navigator`, `DOMParser`) here: anything platform-specific is passed in by the app. Tests live in `packages/core/test` (Vitest, TZ Asia/Kolkata).
- Workspace rules: the root `overrides` pins `react`/`react-dom`/`react-is` to the version the current Expo SDK requires (19.3.0 for SDK 58); keep one copy, since React Native breaks on duplicates. `electron` is an exact version (electron-builder can't read a range once it's hoisted to the root). `apps/desktop/package.json` keeps `"productName": "desktopapp"`: Electron names the userData folder after it in dev, so changing it silently resets everyone's sign-in, drafts and settings. electron-builder artifact names use `${productName}` (the scoped package name contains a slash). `@daily-status/core` is a devDependency of desktop: Vite bundles it, so it must not ship in `app.asar`.
- gluestack: mobile pins lean `@react-types/*` devDependencies because their newest releases pull in all of Adobe's React Spectrum (1.3 GB), and npm ignores `overrides` for them; `metro.config.js` adds `mjs` to `sourceExts` for `react-aria`'s exports. gluestack templates are our code: restyle with our tokens, and never use `AvatarFallbackText` (its `charAt(0)` splits conjuncts). On Android, weight-600 text in a content-sized box is measured narrower than drawn and loses its last letter; button labels use `font-semibold android:font-bold`, and other tight labels should too.
- Adding packages: always from the root (`npm install -w @daily-status/mobile <pkg>@<version>`), taking native versions from `node_modules/expo/bundledNativeModules.json`. `npx expo install` inside `apps/mobile` nests packages under `apps/mobile/node_modules`, which breaks the hoisted Expo CLI (`Cannot find module 'expo-router/...'`); if that happens, regenerate the lockfile rather than patching it. React Native 0.88 supports Node 22/24/26.

ESLint rejects `StyleSheet.create` in `apps/mobile/src`. Before writing UI, reuse `components/ui.tsx`, then `components/gs`; extend a component through props rather than adding a second one. New gluestack components are copied from the CLI's `starter-kit-expo-uniwind` (not `npx gluestack-ui init`, whose `--uniwind` is broken) and restyled with our tokens. Pressables keep their accessibility role and label; give a pressable that can be `busy` an explicit `accessibilityLabel`, or Android reads it only as "busy". Before an Android release build, delete `android/app/build/generated/assets/react/release/www.bundle`: it is never cleared, so stale editor bundles end up in the APK. `app/_layout.tsx` imports `lib/supabase` first, provides `I18nContext`/`ThemeContext`/`ProfileContext`, holds the splash until `useAuth` settles, and guards `(app)` vs `sign-in` with `Stack.Protected`; `(app)/_layout` is a Stack (app lock, realtime, reminders, `QuickCommentProvider`) holding the `(tabs)` group and `details/[kind]/[id]` (an update or task plus its comments, own header, pushed over the tabs so the lock covers it); the Team and Assign tasks (`board/`: list with status filter, `board/new` form with `components/PeoplePicker`) tabs are `Tabs.Protected` on `role === 'admin'`; Today, History and My tasks are staff-only (admins land on Team, get no reminders and no reminder setting). Tabs come from `expo-router/js-tabs` (plain `expo-router`'s `Tabs` is deprecated) with a custom `components/LiquidTabBar.tsx`: a pill positioned absolutely over the screens (no background strip), whose active capsule slides with one 260ms ease-out timing, instant under reduced motion. Tab screens pad their scroll content by `useTabBarInset()` (`lib/tabBar.ts`; `Screen` does it, FlatLists set `contentContainerStyle`); screens under a stack header pass `Screen underHeader`. It uses the vendored tab bar API (`emitter.emit('tabPress')` then `navigateToTab`), not React Navigation's `navigation`; only the active tab shows its label, every tab keeps `accessibilityLabel` + `selected`. `lib/supabase.ts` reads `EXPO_PUBLIC_*` from `apps/mobile/.env` (written out as `process.env.NAME`, or Expo won't inline them) and runs token refresh only while the app is active. `lib/storage.ts`: `prefs` (sync expo-sqlite kv-store, so the first frame has the saved language/theme) and `sessionStorage` (session AES-GCM-encrypted via expo-crypto, key in SecureStore `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`; uses the kv-store's sync calls because overlapping async transactions fail). Theme colours live once in core `palettes.ts`: `test/palettes.test.ts` fails if `main.css` disagrees and regenerates mobile's `src/theme.gen.css` (Uniwind themes, `npx vitest -u` in `packages/core`; theme names must also match `extraThemes` in `metro.config.js`, and Metro needs `--clear` after a change). On the gluestack branch Uniwind owns the active theme: the root layout calls `Uniwind.setTheme` with the saved choice and reads `useUniwind().theme`; nothing else may set it or read `useColorScheme()`, since `setTheme` also forces React Native's colour scheme. `global.css` maps desktop's token names (`bg-canvas`, `text-fg-2`…) and gluestack's (`primary`, `background`…) onto them; gluestack's `accent` clashes with ours, so templates must not use it, nor `dark:` (it only matches the plain dark theme). `components/ui.tsx` primitives (same API on either styling; 48pt targets, `KeyboardAvoidingView` padding on both platforms since Android is edge to edge). Hermes has no `Intl.Segmenter`: core code must not assume it (`firstGrapheme` falls back to a virama-aware regex). Test with dev builds (`expo run:*`), not Expo Go. `dom/EditorPage.tsx` is a `'use dom'` component (WebView, via `@expo/dom-webview`) that renders the shared editor in `compact` mode with Tailwind (`postcss.config.mjs`, `dom/editor.css`); `react-native-web` is required for DOM components, don't remove it. Native passes the palette as resolved CSS vars (`cssVars`, no `light-dark()`: older iOS WebViews lack it), `fontScale`, `lang`, and async callbacks; Supabase never enters the WebView (`loadPlan` runs natively). Editor changes go into a ref, not state, since each re-render re-sends every prop into the WebView; `docKey` swaps the document without remounting the WebView. The editor has two modes (`useEditorFit`, `lib/editor.ts`). At rest the page keeps its natural height (at least `rest`) and reports it (`onContentHeight`, ResizeObserver), the WebView grows to match, and `nestedScrollEnabled`/`scrollEnabled` are off so a drag on the editor scrolls the screen (Expo's DOM WebView otherwise claims every touch on Android). While the writing area has focus and the keyboard is up (`typing`), `html[data-fit]` makes the page fill the WebView, the WebView is sized so the editor box exactly fills the space above the keyboard (measured with `measureInWindow` + the keyboard's `screenY`, so headers count), the screen scrolls to that box (again after 250ms, as the first scroll can be clamped), the writing area scrolls inside (`contain: size`, box `overflow-clip` so large text can't squeeze it out) and the page scrolls the caret back into view. Focus is tracked across the whole `[data-editor-box]` (link box included). In `compact` the chips are one sideways row and the toolbar is a main row plus "More". `editorFontScale` caps its text at 1.5x on Android, whose non-linear font scaling keeps native body text near that at the 2x setting; focusing it scrolls the screen to it. ESLint forbids importing `@daily-status/editor`/`@tiptap/*` code in `apps/mobile` outside `src/dom` (types are fine), and `babel.config.js` keeps the React Compiler off `packages/editor`. Cards render natively from core's `richTree` (`components/RichText.tsx`), so only allowlisted nodes reach the screen. Today (`(app)/(tabs)/index.tsx`: date in the route param, validated; drafts in `prefs`, debounced) and History (`(app)/(tabs)/history.tsx`: FlatList, inline delete confirm, Edit → Today with `date`). Editor screens share `lib/editor.ts` (`useEditorContent`: content ref + `flush()` that blurs the page so a last Write-in word converts, then waits for the change; `useWriteLang`: one store over `prefs`), `lib/hours.ts` + `components/HoursField.tsx` (half-hour − / + stepper), and `lib/refresh.ts` (`usePullToRefresh`). Team (admin) is a stack: `team/index` (Daily feed / People; filters live in the parent), `team/[id]` (person: presets, calendar, timeline), `team/edit/[statusId]` (saves with `updateStatus` by id, never the upsert). `team/_layout` redirects non-admins (deep links too); route ids go through `uuidParam`. Shared data is live on both apps through core `live.ts`: `useRealtimeSync(userId)` (mounted once in the signed-in layout / desktop `Workspace`) subscribes to `daily_statuses`, `profiles`, `tasks` and `task_assignments` (RLS-filtered; bursts debounced, a reconnect refetches) and bumps one counter; `useLiveQuery` puts it in the key and keeps the last data on screen while refetching (third tuple value = background refresh, for pull spinners). Own saves call `bumpLive()` too. Use `useLiveQuery`, not `useQuery`, for anything another person or device can change. Settings (`(app)/(tabs)/settings.tsx`): language, theme radios ("Match my phone"), reminder, app lock. App lock (`lib/appLock.ts`, `components/AppLock.tsx`, rules in core `appLock.ts`): opt-in per user in `prefs`, turning it on needs a successful scan; `AppLockGate` in `(app)/_layout` locks at launch (not right after a password/code sign-in: `SIGNED_IN` vs `INITIAL_SESSION`) and after 30s+ in `background` (never on `inactive`, which the Face ID sheet itself causes), covers the screen while the app is not in front, prompts once per lock with the phone passcode as fallback, and offers password sign-in (which also turns the lock off if Face ID/fingerprints were removed). The session stays as is; only the UI is gated. `NSFaceIDUsageDescription` comes from the `expo-local-authentication` plugin in `app.json`. `lib/reminder.ts` schedules one-shot local notifications (expo-notifications, no push: the plugin has `enableRemoteNotifications: false`) at the chosen time on each workday for 4 weeks, with fixed ids `reminder-YYYY-MM-DD` and a queue so overlapping syncs can't duplicate; it resyncs on sign-in, foreground, language/setting changes and `markToday()` (call it wherever today's own update is saved or deleted), asks permission once on first sign-in, cancels everything on sign-out, and a tap opens Today. Android fires exactly only if the exact-alarm permission is granted (Android 14+ denies it by default), else up to an hour late: turning the reminder on opens Android's "Alarms & reminders" page once, and Settings shows the next reminder plus a warning with an allow link (`allowExact`) while it's off; never add `USE_EXACT_ALARM` (Play restricts it). Reminders also show while the app is open (banner, list and sound). Long lists are FlatLists with everything else in `ListHeaderComponent`; `SubmissionCalendar` is memoised and formats dates at local midnight (no `timeZone` option).

Placeholders use `--placeholder`, not `fg-3`. Scrollbars are global `::-webkit-scrollbar` rules coloured by `--scrollbar-thumb` and faded via the registered `--sb-alpha` (hover, or `[data-scrolling]` from `lib/scrollbars.ts`); never set `scrollbar-color`/`scrollbar-width` on an element (Chromium then drops the custom scrollbar for its whole subtree) except through the `no-scrollbar` utility. Playwright checks of hover, timers or transitions need the window on top with `setBackgroundThrottling(false)`, or Chromium freezes them. `Notice` tone `bad` is an alert and `ok` a status; others are silent.

Security: `sandbox: true` and `contextIsolation: true`. Never expose `ipcRenderer` directly. The CSP in `src/renderer/index.html` must allow any new network origin in `connect-src`.
Renderer env vars must be prefixed `VITE_` or `RENDERER_VITE_`. `VITE_` vars are also bundled into main and preload, so never put secrets in them.

## The 4 Laws

These rules apply to every session and sub-agent working in this repo.

### 1. Code Density Limit

- Write dense, idiomatic code: arrow functions, ternaries, array methods (`map`/`filter`/`reduce`), destructuring, optional chaining.
- If something can be written cleanly in 2–4 lines, **do not** expand it into a 10+ line block.
- No unnecessary intermediate variables. Inline single-use values unless naming them clarifies intent.
- Dense must still be readable: no nested ternaries more than 2 deep, no clever one-liners that hide bugs.
- After generating code, run the `code-simplifier` skill.

### 2. Anti-AI Slop

- Code must read like an experienced senior engineer wrote it. Follow the `humanizer` skill.
- No comments that restate _what_ the code does. A comment is allowed only for a non-obvious _why_, on one line.
- No boilerplate wrappers, pass-through helpers, defensive try/catch with nothing to handle, or banner comments.
- Use organic, conventional names (`res`, `err`, `ctx`, `cfg`) over machine-verbose ones.

### 3. Token Hygiene

- When the conversation history gets long, tell the user to run `/compact`. Claude cannot trigger slash commands itself.
- Never print raw, unpaginated output. Cap every output:
  - `cmd | head -n 20`, `tail -n 30`, `grep -n <pattern> | head`
  - `ls` a specific directory, never a recursive tree of the repo
  - `git log --oneline -n 10`, `git diff --stat` before a full diff
- Read files with line ranges once the relevant region is known.
- Never read `node_modules/`, `dist/`, `build/`, lockfiles, or logs unless explicitly asked.

### 4. Run & Maintenance Routine

After every file edit, run the `spartan-quality-gate` skill. A `PostToolUse` hook (`.claude/hooks/post-edit.sh`) auto-formats edited files once a formatter is configured.

| Step      | Command                                                                                    |
| --------- | ------------------------------------------------------------------------------------------ |
| Format    | `npx prettier --write <file>` (auto via hook)                                              |
| Lint      | `npx eslint <files>` / `npm run lint`                                                      |
| Typecheck | `npm run typecheck`                                                                        |
| Test      | `npm test` (Vitest in `packages/core`; the apps have no UI tests yet)                      |
| Dev run   | `npm run dev` (from Claude/VS Code: `env -u ELECTRON_RUN_AS_NODE npm run dev`)             |
| Mobile    | `npm run android` / `npm run ios` (build + install dev app), then `npm run mobile` (Metro) |
| Build     | `npm run build` / `npm run build:mac` / `npm run build:win` (x64, no Rosetta needed)       |

Pipe all of these through `| tail -n 30` so only failures and summaries show.

**Self-maintenance:** after each major feature module (new IPC channel group, route, folder or test suite), update the Layout section and the command table here. Keep this file under 300 lines.

## Advisor Subsystem

- The user enables the advisor with `/advisor opus` or `/advisor fable`. It's a stronger, server-side reviewer model that sees the full transcript.
- Consult it:
  - **before** committing to an approach on architecture or multi-step work
  - when **stuck** (recurring errors, approach not converging)
  - **before declaring a complex task done**: the final "Reviewed" completion pass
- A complex task is done only after the advisor's review is addressed. Then report it as **Reviewed**.

## Workflow

Non-trivial features follow the `dev-workflow` skill: **Clarify → Spec → Plan → Execute → Review**.
Typed code follows the `type-discipline` skill.
